# Lombiq UI Testing Toolbox for Orchard Core 17.0.0

**Release Date:** Not yet released

**Full Changelog**: https://github.com/Lombiq/UI-Testing-Toolbox/compare/v16.0.0...v17.0.0

## Breaking Changes

### Upgrade to Atata 4

This is a dependency upgrade with major breaking changes of its own. Make sure to check [their upgrade guide](https://atata.io/upgrade/to-atata-4/) if your code uses any Atata features directly.

### Removed code previously marked as `[Obsolete]`

If your project hasn't upgraded to UITT 16.0.0 yet, do it first and follow the instructions in the build warnings.

### All `ExecuteTestAsync`, `ExecuteTestAfterSetupAsync` and similar methods in `OrchardCoreUITestBase<TEntryPoint>` are now obsolete

We have introduced a new [builder pattern](#test-builder-methods) to streamline test invocation without a lot of slightly-different test execution methods. To reduce maintenance burden, the current test and setup execution methods are marked obsolete and will be removed in future releases.

## New features

### Test builder methods

We have introduced a new builder-style approach with new methods in `Lombiq.Tests.UI.UITestBase`. This makes test invocation much more straight forward and flexible. You can reproduce something like the old `ExecuteTestAfterSetupAsync` method by chaining calls like this:

```csharp
[Fact]
public Task MyTest() =>
    UseSetup(context => context.GoToSetupAndSetupOrchardCoreAsync(recipe))
        .AddTest(context => { ... })
        .AddSyncConfiguration(configuration => { ... })
        .RunAsync();
```

Or you can call `UseSetup` in the constructor of the test class (or the base shared test base class). You can also call `AddConfiguration` or `AddSyncConfiguration` in the constructor, to make shared configuration. Also, you can call them multiple times, and they are scheduled in a single queue for the test instance, so you can use it to group configurations. As a shortcut, you can pass the final test function directly `RunAsync` as well. So think about something like this:

```csharp
public class MyTests : UITestBase
{
    public MyTests(ITestOutputHelper testOutputHelper)
        : base(testOutputHelper)
    {
        // Typically you just want one setup for all tests.
        UseSetup(...);
        // You can have some shared configuration for all tests.
        AddSyncConfiguration(...);
    }
    
    // The simplest UI test is just calling RunAsync with the shared configs.
    public Task MySimpleTest() => RunAsync(context => { ... });
    
    // This test adds further configuration. When RunAsync is called, first the configuration in the constructor is
    // applied, then this method's.
    public Task MyTest() =>
        AddSyncConfiguration(...)
        .RunAsync(context => { ... });
}
```

For more details, take a look at the updated [Lombiq.Tests.UI.Samples](../../../Lombiq.Tests.UI.Samples/Readme.md)!

## Updates

### Cleaned-up stack traces

Several internal methods were decorated with the [`[StackTraceHidden]`](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.stacktracehiddenattribute?view=net-10.0) attribute, to make debugging your UI tests easier.
